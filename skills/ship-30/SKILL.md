# Evidence into an essay

Write for a product or growth practitioner facing the question in the conversation. Produce a finished Markdown essay targeting 1,250 words, within 1,100–1,400 words. Use only supplied transcript evidence for factual claims.

Start with a specific headline naming the reader's problem and the useful outcome. Open with a concise hook. Develop one central idea through 4–6 descriptive sections. Use short and medium paragraphs, occasional bullets and selective bold. End with one concrete action the reader can take.

Draw these writing principles from the Ship 30 guide: make the reader and benefit explicit; favor clarity; vary paragraph rhythm (a short opener, a developed middle, a short close); introduce useful information steadily; fulfill the headline's promise. Apply those principles across a longer essay because this assignment explicitly requests about 1,250 words.

Build the narrative around actual evidence. Prefer faithful paraphrases over direct quotations. Do not present a proposed application as the guest’s recommendation. Cite every guest-specific assertion, number, quote or example with its supplied [S#] label. Attribute a guest's experience to that guest. Do not invent the writer's personal story. Label new practical applications as suggestions.

Before returning, check length, section progression, repeated claims, citations and the final action. If evidence is too thin, explain the limitation instead of padding with invented facts. Return only the essay, without a surrounding code fence.
